目前建置狀態：已將 `vue-tsc` 1.8.27 更新至 3.3.11，加入 Node.js 24 型別並修正新版檢查器揭露的既有型別錯誤；`npm run build` 已在 Node.js 24 下完整通過。左上品牌文字縮寫亦已由共用 SVG 字幕聲波圖示取代。

第二輪進度：已建立內建 SVG 導覽圖示系統，取代側欄 emoji／隱藏圖示；一般設定、ASR 模型管理、推薦翻譯模型、字幕外觀與其主要子元件已統一面板、主要操作及狀態視覺。Llama 與自訂模型對話框已補上 dialog 語意和標題關聯，主要頁首與伺服器操作移除裝飾 emoji。桌面實機頁面已逐頁檢查，完整 `npm run build` 通過。第二輪不代表整體計畫完成，後續仍須完成其餘控制項、窄版／縮放矩陣、端到端音源、原生字幕窗與安裝包驗收。

第二輪追加：浮動字幕窗新增字幕時改用 280ms 緩出位移。原生 Qt 視窗會讓現有字幕同步平滑上移、最新字幕由底部邊緣進入，最舊字幕在頂部邊緣裁切並淡出；同一字幕的串流文字修訂只維持逐字更新，不重啟整列動畫。Web 備援字幕窗使用相同時長的 move／enter／leave 過渡，並尊重 reduced-motion 偏好。

下載狀態修正：多連線下載不再等完整 8 MB range 及其前序 future 完成才更新畫面。四條連線每接收 1 MB 即彙總回報網路進度，檔案仍依原順序寫入連續 `.part`，保留安全續傳與失敗退回單線的既有行為。

第三輪完成：首頁四種音源、模型、啟停、日誌與分享區改用共用 SVG 圖示，移除主操作區的裝飾性 emoji；VAD、翻譯、Llama 與模型頁的區段標題、空狀態與警示語意已統一。新增小螢幕內邊距、長路徑斷行、可見焦點、40px 主要操作高度與 reduced-motion 規則。

第四輪完成：以本地 HTTP 音訊、本地影片、NVIDIA Broadcast 麥克風及 Voicemeeter Loopback 實際執行啟動、持續運行與停止。URL／檔案產生真實 SenseVoice CPU 字幕 SSE，麥克風與系統音訊完成模型預載及設備開啟。回歸過程發現已儲存的舊 ASR 布林旗標會覆蓋首頁新選擇，現已在每個任務開始時正規化為單一引擎，並加入回歸測試。字幕外觀 PATCH 已實測讀回並復原，`/subtitle-settings`、`/subtitle`、`/desktop`、`/mobile` 皆能實際載入。

## 目標與範圍

以本次深色商業介面示意圖作為全產品視覺方向，統一所有頁面的導覽、表單、按鈕、面板、字級、狀態與間距。保留所有既有功能及設定能力，並維持「主視窗控制、獨立浮動字幕窗觀看」的操作方式。

全頁面風格一致是必要交付條件，不是首頁完成後的選配工作。所有設定分頁、模型頁、詞庫、教學、字幕設定及彈出視窗均須納入；不得以個別頁面功能較複雜為由保留另一套舊樣式。不同用途可採不同布局，但必須使用相同設計規範、共用元件與互動語意。

示意圖是視覺參考，不是功能規格的全部。以現行程式和行為盤點為功能基準；圖上沒畫出的功能仍須保留。圖中的連線、就緒、模型下載等為示範資料，正式畫面必須由真實狀態驅動。

本次已確認目前技術為 Vue 3、Pinia、Vue Router、TypeScript、Tailwind CSS、Vite；桌面入口使用 Qt，浮動字幕預設為 NativeSubtitleWindow，並有 Web 字幕備援。採漸進式前端更新，沿用既有 API、設定格式、事件同步及桌面橋接。

本次不包含：新增場景方案、批次任務、字幕編輯、歷史資料庫，或新增原生視窗能力。這些可另開功能計畫，不混入外觀更新。若現有功能已具備，照常保留。

## 設計落地規格

- 左側保留完整分組導覽，不把專業設定移到難以找到的位置；窄視窗採抽屜導覽。
- 頂部提供頁面名稱與真實連線狀態。版本、更新、教學均保有入口。
- 首頁中央依序為四種音訊來源、來源專屬輸入、語言與翻譯開關、引擎與模型、開始／停止。
- 右側放浮動字幕窗入口、字幕外觀捷徑及字幕分享。只提供已具備能力的控制。
- 本地 LLM 快速控制保持可見，含模型名稱、載入／就緒／錯誤與啟停能力。
- 日誌以有限高度呈現最近內容，可展開完整日誌、清除及維持既有捲動行為。
- 圖中下方獨立字幕窗僅是展示排版；不得實作成主頁的常駐字幕閱讀區。浮動窗仍是另一個視窗。
- 深藍灰背景、克制的藍色強調；成功／警告／失敗另用一致語意色。主要動作以開始／停止為主，避免每個按鈕都使用高彩度漸層。
- 一般內容以 14–16px 為起點，次要文字以 12–13px 為起點；避免重要資訊使用 9–10px。整合 4/8px 間距尺度與一致圓角。
- 沿用專案相容的下拉選單行為，補足標籤、鍵盤焦點、停用原因、載入及錯誤狀態。避免大面積 blur、持續動畫和整頁 paint containment。
- 不覆蓋字幕專用透明頁面的背景規則。/subtitle、/desktop、/mobile 的既有操作介面依用途套用共用規範，字幕內容則保留使用者自訂樣式；獨立字幕設定窗與內嵌設定頁使用相同元件，以容器適配布局。

## 全頁面一致性規範

### 單一設計來源

1. 在集中管理的設計 tokens 定義背景層級、文字、邊框、主色、語意色、字級、間距、圓角及焦點。各頁引用相同變數，不自行複製一套近似值。
2. 建立共用頁首、區段標題、表單欄位、按鈕、下拉選單、開關、狀態提示、表格、分頁、對話框及空白／載入／錯誤呈現。既有元件優先整合，純樣式可共用 class，不為每個元素新增包裝元件。
3. 統一主要、次要、低強調及破壞性操作的外觀；相同動作在不同頁面使用同樣名稱、圖示與回饋。一般圖示採同一套來源與尺寸，避免各頁混用不同風格的 emoji 和圖示。
4. 統一頁首標題、說明、狀態及操作位置。設定頁採一致的欄位標籤、說明、錯誤與分組間距；模型頁和詞庫頁沿用一致的清單、篩選與操作規則。
5. 相同功能使用相同狀態語意，但不強行改變操作流程。例如自動儲存頁呈現儲存狀態，明確提交的對話框仍保留儲存／取消，不為統一外觀取消既有操作。
6. 響應式布局、鍵盤焦點、懸停、停用及載入效果集中定義。共用元件更新後，要回歸檢查所有使用頁面。

## 分階段實作

### 第一階段：基準與設計規格

1. 記錄工作樹狀態，在 codex/ 分支進行後續實作，保留其他未提交工作。
2. 在正常後端運行環境逐頁截圖，完成全部控制項及條件顯示欄位盤點。
3. 補齊首頁的未配置、可啟動、下載中、轉譯中、停止中、失敗、後端斷線等狀態設計。
4. 以商業首頁的視覺語言補定設定頁、模型清單頁、詞庫、教學、字幕外觀頁與對話框規格，建立代表性畫面並排對照。首頁示意圖不能直接推定其他頁面已設計完成。
5. 建立頁面／子元件／彈出視窗與共用元件的對照表，將全部設定分頁及條件顯示內容納入覆蓋清單。

交付：功能對照表、畫面基準、設計 tokens、狀態規格。進入下一階段前，現有功能均需有明確的新位置。

### 第二階段：全域樣式與導覽

主要檔案：src/style.css、src/components/MainLayout.vue、UiSelect.vue；建立集中 tokens，整合共用的頁首、按鈕、欄位、面板、狀態、表格及對話框規範。

先套用色彩、字級、間距、焦點與導覽選取規則。維持路由及 query tab，不先搬動業務邏輯。限定主介面樣式作用範圍，驗證所有字幕透明路由。

先製作共用元件的狀態展示，涵蓋預設、懸停、焦點、停用、載入、成功與失敗，再套用到各頁，避免各頁自行解讀風格。

驗收：全部導覽與深連結可達、桌面／窄視窗可用、下拉選單在 Qt 中正常、字幕背景未變成不透明；代表性表單、模型清單與對話框可使用同一套規範。

### 第三階段：首頁改版

主要檔案：src/views/HomeView.vue，必要時拆成音訊來源、模型設定、本地 LLM、字幕分享及日誌展示元件。

保持既有 store、API 呼叫、watch、事件與桌面橋接的生命週期；先搬動展示區塊，避免同時大改流程。日誌收合不得停止訂閱或遺失原有顯示能力。首頁的設定、下載及啟停仍使用同一份狀態。

依真實資料呈現就緒／錯誤。後端無法連接時顯示未連線，不以預設設定判定模型已安裝或分享已運行。既有 ffmpeg 與更新通知保留。

驗收：四種來源均有完整操作入口，模型下載可接續開始，啟停及本地 LLM 正常，分享與日誌可用，主頁沒有重複的字幕閱讀區。

### 第四階段：全部設定、模型、詞庫與教學頁一致化

主要檔案：SettingsView.vue、LlamaModelsView.vue、TranslationModelsView.vue、LlamaSettings.vue、WhisperFilterSettings.vue、AsrModelGroup.vue、GuideView.vue。

逐頁調整標題、分組、欄位、描述、按鈕及表格。保留進階欄位，可收合但不可省略。模型狀態、進度、失敗與取消等既有操作要完整呈現。術語表保留大資料量處理，不因新樣式改為一次渲染所有資料。

按頁面覆蓋清單逐列執行，同時處理該頁的子元件、條件區塊與對話框。以集中 tokens 和共用元件替換重複樣式，移除已無用途的舊規則；不得只替換頁面背景而留下另一套表單、表格或提示樣式。

儲存狀態區分未載入、載入中、未修改、儲存中、成功與失敗；不得將 idle 直接等同已儲存。處理視覺改版中遇到的狀態錯誤時另列明確變更與驗收。

驗收：欄位清單逐項核對，現有 YAML／設定值不被預設值覆蓋，匯入匯出與往返儲存結果一致，API Key 仍遮罩且不進入展示資料或截圖。

### 第五階段：字幕設定與多視窗驗證

主要檔案：SubtitleSettingsView.vue；FloatingSubtitleView.vue、DesktopSubtitleView.vue、MobileSubtitleView.vue 的既有控制及狀態介面納入一致化，字幕渲染本體以回歸驗證為主。app/main.py、原生字幕渲染器原則上不改。

字幕設定頁套用相同視覺，保留內嵌與獨立視窗兩種路徑。設定預覽可以存在於外觀頁，但不取代實際浮動窗。確認 HTTP 儲存回應、即時套用與重新開啟後的結果；同時保留現有原生及 Web 備援路徑。

驗收：字體、顏色、透明度、顯示數量、雙語、時間與延遲均能實際套用；原生窗、瀏覽器字幕及分享頁各自正常，拖動／縮放等原有能力無退化。

### 第六階段：整合驗收與交付

完成 TypeScript／Vite 建置及相關既有測試。新增測試只針對有實際風險的狀態與行為，不為純 CSS 寫重複測試。

增加全頁面視覺驗收：使用相同視窗尺寸、縮放與資料狀態擷取頁面，將首頁、各設定分頁、模型、詞庫、教學、字幕設定及對話框並排比較。逐項核對字級、間距、按鈕層級、圖示、欄位、表格及狀態。掃描殘留舊配色與重複樣式，再以實際渲染確認；文字搜尋不能代替視覺驗收。

Vite 的正式輸出目錄為 app/backend/static，且 emptyOutDir=true；建置前先確認其中沒有無關變更。需由 FastAPI／Qt 實際載入新的輸出驗證，不能僅在 Vite 預覽通過。

若交付範圍含安裝包，再建置並驗證目標套件，實際開啟主頁與浮動窗；原始碼建置成功不代表既有 EXE 已更新。發布與上傳另依使用者指示執行。

交付：共用設計規範、完整頁面覆蓋表、全頁面與代表性狀態截圖、並排對照、功能對照表、測試結果、已知限制、變更清單及回退方式。

## 驗收矩陣

| 面向 | 驗收要求 |
| --- | --- |
| 功能完整性 | 盤點的全部控制項具備新位置；無遺失設定、缺少入口或空按鈕 |
| 全頁面一致性 | 覆蓋清單所有列完成；相同元件、狀態與操作使用同一套視覺規範，沒有遺留舊風格頁面或彈出視窗 |
| 共用元件 | 同類控制引用集中 tokens／共用元件或樣式；同一種狀態不因所在頁面不同而改變顏色、名稱或操作回饋 |
| 視覺 | 1440×900、1280×800、1024×768 及實際桌面最小尺寸無重疊／裁切；長路徑與長模型名稱可讀 |
| 縮放／行動 | Windows 125%／150%、瀏覽器 200% 縮放及 390px 寬度；允許合理捲動，重要操作可達 |
| 四種來源 | 可控制的短音檔／音源各跑一輪：選擇、開始、輸出、停止；外部平台受限需記錄原因，不能以其他來源代替驗收 |
| 錯誤狀態 | 後端離線、無來源、裝置失效、未下載模型、下載失敗、服務憑證或連線失敗、儲存失敗都有正確提示及恢復入口 |
| 字幕鏈路 | 真實音訊 → 辨識 → 翻譯 → 獨立字幕窗；停止後狀態同步，外觀即時套用與重啟保留 |
| 多視窗 | 主頁、設定頁、Qt 字幕設定彈窗、原生字幕窗、Web 備援、桌面／手機分享頁 |
| 可及性 | 鍵盤到達重要控制、焦點可見、表單標籤完整；必要文字對比實測，不以截圖宣稱合規 |
| 性能 | 同機、同模型、同音源比較前後 CPU／RAM／GPU、UI 流暢度與字幕延遲；若持續出現超出基準波動的退化，定位並修正後再交付 |

## 回退與實施順序

按全域樣式、首頁、設定／模型、字幕設定分批提交；每批保留可運行狀態，失敗可針對該批回退。前端輸出與來源保持匹配，不用 git reset/clean 覆蓋使用者工作。不改設定 schema，避免僅外觀更新卻需要資料遷移。

建議先完成第二、三階段，交付可操作的新首頁作為第一個檢查點，再依同一視覺規格逐頁推進。第一個檢查點不是整體完成；只有頁面覆蓋表全部完成、全頁面風格一致性通過、全部功能回歸與多視窗驗證通過，才算完成本計畫。任何未完成的頁面或狀態必須列為待辦，不能以首頁已改版宣告交付完成。
