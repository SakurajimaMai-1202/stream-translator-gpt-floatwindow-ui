# Stream Translator v1.5.0 更新說明

更新日期：2026-10-10。CPU、CUDA、ROCm Experimental 三種套件已完成重新建置。

本版 Full／App Update 套件包含全站介面統一、指定應用程式收音、llama.cpp 單卡選擇與 Index 模型推薦，以及首次設定、翻譯、字幕與手動更新修正。

## 新增功能

### 一致、清楚的操作介面

- 首頁、教學、所有設定分頁、模型管理與字幕控制介面統一深色配色、字級、卡片、按鈕及表單樣式，遵循 Apple Design 的清楚層級與常用操作優先原則。
- Llama 執行設定集中模型、顯卡、常用參數與試譯；Runtime、配置預設及進階參數可展開管理。
- ASR 模型管理優先呈現模型清單與下載狀態；翻譯選項集中後端、語言及模型策略，自訂模型、提示詞與進階設定收進展開區域。
- 修正顯卡選單的白色區域，統一深色選單；補上鍵盤焦點、窄視窗排版與減少動態支援。字幕畫布仍保留使用者自訂字型、顏色、透明度與位置。

### 雙顯卡與本機翻譯模型

- llama.cpp 以實際 Runtime 列舉裝置，支援手動指定單張顯卡；自動選擇優先使用可用獨顯，預設排除內顯，也可手動允許內顯。
- NVIDIA 預設優先 CUDA；AMD 與 Intel Arc 獨顯預設推薦 Vulkan。這是本機翻譯 Runtime 的選擇，ASR 套件類型仍依原配置運作。
- 顯示已指定的顯卡與模型實際卸載確認；保存裝置名稱，裝置消失或編號對應改變時提示，避免靜默切換。
- 推薦模型加入 [Index-Translate-2B](https://huggingface.co/IndexTeam/Index-Translate-2B) 與 [Index-Translate-9B-GGUF](https://huggingface.co/IndexTeam/Index-Translate-9B-GGUF)，提供量化大小、顯存估算及部署參數；2B 使用其[官方 GGUF](https://huggingface.co/IndexTeam/Index-Translate-2B-GGUF) 下載來源。
- 修正 temperature=0、top_k=0 等合法零值在設定載入時被預設值覆蓋的問題。

### 指定應用程式音訊

- 首頁及首次設定可選擇開啟中的應用程式視窗，先測試收音，再使用原有 ASR／字幕流程。
- 擷取目標程序及其子程序；瀏覽器可能共用程序，不能保證單一分頁或視窗隔離。需要支援 Process Loopback 的 Windows build 20348 以上環境。
- 每次啟動重新驗證目標；程式退出時停止並提示，不自動改收系統音訊或麥克風。重新開啟應用程式後需重新選擇。

### 驗證範圍

前端建置與本機瀏覽器排版／選單檢查通過；GPU 選擇已在 RTX 4060 Ti 驗證實際卸載與短輸出；指定應用程式收音已以受控程序與 SenseVoice CPU 跑通 ASR／字幕流程。尚未完成 AMD／Intel 雙顯卡實機、Index 2B／9B 推論、使用者實際多分頁／長時間直播，以及新版套件完整安裝與更新驗收。三種套件建置與 ZIP 完整性檢查已完成，這不等同於上述實機與完整更新流程驗收。

## 其他重點更新

### 更清楚的首次設定與來源測試

- 首次設定先選擇音訊來源與辨識語言，再準備對應的入門 ASR 模型，避免一次下載多個不需要的模型。
- 首頁顯示音訊來源與語音辨識的準備狀態；只使用語音辨識時，不會被翻譯設定阻擋。
- 直播網址、本機影音檔、系統音訊與麥克風提供各自的來源檢查，協助確認網址解析、檔案音軌或裝置收音是否正常。
- 區分「裝置可開啟但目前無聲」與「已收到音訊」，檢查失敗時提供原因及下一步操作。

### 翻譯設定與繁體中文輸出

- HY-MT2 與 Index 分別保存端點、模型、API 金鑰、提示詞及優化設定，切換時不再互相覆寫。
- 修正部分相容 API 回覆被誤判為空白的問題；試譯介面更清楚地顯示空輸出、錯誤與檢查結果。
- 使用外部翻譯端點時，不再誤啟動本機 llama.cpp 模型。
- 改善情境詞庫、別名、前文與風格控制；檢查空輸出、前文重述、固定詞及輸出格式，並限制重試次數。
- 繁體中文翻譯在最終送出前統一經 OpenCC 轉換，涵蓋各翻譯管道及自訂提示詞；轉換失敗時阻擋未轉換的文字。

### ASR、字幕與啟動穩定性

- 改善本地 ASR 短片段與日文未完句的字幕組裝：完整句立即送出，未完片段採有限等待，合併不會持續延後等待期限。
- 清理 `<unk>` 等非字幕標記，改善多行字幕輸出，避免診斷資訊混入字幕。
- 修正 CPU 打包版缺少翻譯策略模組造成的啟動失敗。
- 改善顯示卡名稱辨識與 Intel Arc 自動設定，並保留 llama.cpp 啟動失敗時的實際錯誤原因。

### 手動更新與串流解析

- 手動更新器支援本機 App Update ZIP 與 `.zip.part01`，套用前檢查版本、套件類型、ZIP 內容及相容性。
- 分割檔放在同一資料夾；旁邊有對應 SHA-256 清單時，更新器會檢查分段及合併後的 ZIP。
- 沿用備份、檔案替換、啟動檢查及失敗回復流程，保留模型與使用者資料。
- 修正 App Update 包含空白 `output` 目錄造成的更新檢查問題，保留安裝目錄既有輸出檔案。
- 更新串流解析元件，內附 yt-dlp nightly、yt-dlp-ejs 與可攜式 Node.js，供 YouTube JavaScript challenge 處理使用。
- App Update 同時替換對應套件的完整 Runtime，讓串流解析與新版管線程式碼一起更新。

## 套件怎麼選

| 使用情境 | 請下載 |
| --- | --- |
| 新安裝，或切換 CPU／CUDA／ROCm 類型 | 對應的 Full package |
| 更新既有安裝，維持相同套件類型 | 對應的 App Update |
| 使用 CPU ASR sidecar 的配置 | 對應的 CPU ASR Sidecar v1.5.0；依原配置使用 |

CPU 適合 CPU 執行環境；CUDA 適合支援 CUDA 的 NVIDIA 顯示卡；ROCm Experimental 為實驗性套件，支援程度依 AMD 顯示卡、驅動及模型而異。

CUDA Full 分為三段，CUDA App Update 分為兩段。請下載同一套件的全部分段，放在同一資料夾；Full 可使用 `merge-full-package.bat` 合併，App Update 可直接在手動更新器選擇 `.zip.part01`。

## 更新步驟

1. 備份 `config.yaml`、Cookies、術語與自訂規則，關閉正在執行的辨識／翻譯任務。
2. 下載與原安裝類型相同的 App Update，並保存 `SHA256SUMS-v1.5.0.txt`；分割包需下載全部分段。
3. 使用手動更新器選擇 ZIP 或第一個分段，依提示完成檢查、關閉程式及套用更新。新安裝或切換套件類型請使用 Full package。
4. 更新後確認版本為 v1.5.0，並測試原本使用的來源、ASR 模型及翻譯方式。
