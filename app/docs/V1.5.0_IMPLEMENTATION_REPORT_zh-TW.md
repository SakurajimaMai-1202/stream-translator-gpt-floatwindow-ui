- 日期：2026-09-27

## 結論

本輪完成 v1.5.0 的可測原始碼骨架與主要 P0 流程：按所選語言只準備一個 ASR 模型、首頁真實準備清單、四類來源各自的檢查與恢復訊息、多模型 capability 欄位，以及同一 trace ID 的後端交付與前端渲染確認時間。沒有變更正式 ASR 或 VAD 預設。

這不是發布完成證明。真實桌面四來源、各模型實際推論、長時間運行、真人新手測試、三 profile 套件與真實升級仍待後續驗收。

## 模型與既有設定相容性

能力資料來源為 `backend/core/asr_model_capabilities.py` 與 `runtime_profiles.py`，UI 不自行維護第二份就緒狀態。所有列出的本機引擎使用共同四來源層；引擎差異由 profile、模型語言與下載契約限制。

| 引擎 | 語言能力 | CPU/GPU 範圍 | context | 備註 |
| --- | --- | --- | --- | --- |
| Faster-Whisper | 多語言／自動 | 依 profile；CPU 簡單模式不下載此系列 | 支援 | tiny 至 large-v3-turbo |
| Qwen3-ASR | 多語言；另有固定日文模型 | GPU 與部分 sherpa CPU 模型 | 支援 | 不將它設為唯一引擎 |
| SenseVoice | 中／粵／英／日／韓 | GPU；CPU INT8 bundle | 未宣稱 | 中文簡單模式候選 |
| Fun-ASR Nano | 3 語言或 31 語言模型 | 依 profile；CPU 僅既有 INT8 bundle | 未宣稱 | 模型能力分開 |
| Parakeet | 固定日／英或 v3 多語言 | GPU；部分 CPU sherpa bundle | 未宣稱 | 日文簡單模式候選 |
| OpenAI transcription API | 遠端 | remote engine | 未宣稱 | 不屬於本機模型下載清單 |

舊設定缺少新 capability 欄位不需遷移；本輪沒有重置自訂模型路徑、API Key、裝置、語言或 VAD 參數。v1.4.10 的 `skipSetup`、`models.storage_path`、`llama.server_exe`、GGUF 路徑與 CPU sidecar import 均保留。

## 驗證命令與結果

測試環境：Windows，`F:\AI\floatwindow`；Python 3.14 system runtime（以 `PYTHONPATH=app;stream-translator-gpt` 載入目前原始碼）；前端使用既有 Node/npm 相依套件。沒有下載模型或呼叫付費服務。

1. `npm run build`（`app/frontend`）：通過；`vue-tsc -b` 與 Vite build，134 modules transformed。
2. `python -m pytest --basetemp app/.codex-test-tmp/v150-l1-20260927 stream-translator-gpt/tests/latency_trace_test.py app/backend/tests/external_process_test.py app/backend/tests/model_download_cancellation_test.py app/backend/tests/source_checks_test.py app/backend/tests/sensevoice_runtime_profile_test.py app/backend/tests/config_persistence_test.py -q`：最終 **68 passed, 1 warning**；warning 是既有 `.pytest_cache` 路徑建立失敗，不是測試案例失敗。第一次使用系統 temp 時有 20 項因 `pytest-of-User` 權限而無法 setup，改用專案內隔離 `--basetemp` 後全數通過。
3. 切片測試初次發現 3 個 legacy 測試未指定模式；修正測試前提後通過，未修改正式 VAD 預設。
4. `python -m compileall -q app/backend/core/source_checks.py app/backend/api/readiness.py`：通過。
5. `git diff --check`：通過；只有既有 Windows LF/CRLF 提示。
6. 以既有 CUDA build runtime 匯入 `backend.main` 並檢查路由：`readiness routes ok`。System Python 缺 FastAPI，因此 API 組裝 smoke 改用相容的 repository runtime；pytest 仍由 system Python 執行。
7. 打包 CUDA DLL 隔離修復：`translator.py` 的 ASR／翻譯子程序改用 `popen_external()`；聚焦測試 28 passed。模擬 GUI 注入 Qt DLL 路徑後，App Update CUDA runtime 成功載入 PyTorch `2.11.0+cu128`、CUDA 12.8，`torch.cuda.is_available() == True`，辨識 RTX 4060 Ti，exit 0。這是原始碼／既有包 runtime smoke，不是重新打包驗證。
