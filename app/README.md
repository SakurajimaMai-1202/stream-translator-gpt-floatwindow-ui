## 安裝與首次設定

### 1. 下載與解壓

| 套件 | 適用情境 | 下載方式 |
| --- | --- | --- |
| CPU | 使用 CPU 語音辨識，不需獨立顯卡 | 下載 `StreamTranslator-win64-CPU-Full.zip` 並解壓。 |
| CUDA | 使用相容 NVIDIA 顯卡進行語音辨識 | 下載 Full 的 `.part01`～`.part03` 及 `merge-full-package.bat`，放在同一資料夾後執行合併，再解壓產生的 ZIP。 |
| ROCm Experimental | 使用相容 AMD 顯卡；支援程度依驅動與模型而異 | 下載 `StreamTranslator-win64-ROCm-Experimental-Full.zip` 並解壓。 |

將程式放在可寫入的資料夾，例如 `D:\Apps\StreamTranslator`，再執行 `Stream Translator.exe`。請使用 Full 完整包；GitHub 提供的 `Source code` 供原始碼使用。

### 2. 選擇操作模式

- **簡單模式：** 依音源與辨識語言準備入門模型，適合先完成第一次轉譯。
- **進階模式：** 自行選擇辨識引擎、模型與進階參數。簡單模式未列出的語言，可切換至進階模式設定。

之後可在側欄切換模式。多數設定會自動儲存，頁面顯示「已自動儲存」後即可繼續操作。首次下載模型需網路與足夠磁碟空間；已下載的模型可重複使用。

### 3. 完成第一次轉譯

1. 選擇音訊來源，設定輸入語言。
2. 執行來源測試，確認程式能收到音訊。
3. 依提示下載辨識模型，或到「ASR 模型管理」自行準備。
4. 需要翻譯時，選擇翻譯後端、目標語言與對應憑證；只需原文字幕時關閉翻譯。
5. 按「啟動即時轉譯」，等待模型載入並觀察原文與譯文。

## 選擇音訊來源

在首頁選擇來源，填寫或選取對應內容。直播網址／檔案按「檢查來源」；麥克風、系統音訊及應用程式音訊按「開始收音測試」。

| 來源 | 操作方式 | 注意事項 |
| --- | --- | --- |
| 直播網址 | 貼上直播或影音網址。 | 支援程度依網站而異；部分內容需要登入權限或 Cookies。 |
| 本機影音 | 選擇電腦上的影音檔案。 | 檔案需包含可讀取的音軌。 |
| 系統音訊 | 選擇 Windows 正在播放聲音的輸出裝置。 | 會收到該裝置上的其他程式聲音；請確認 Windows 播放裝置一致。 |
| 麥克風 | 選擇要使用的麥克風。 | 確認 Windows 已允許麥克風存取，並檢查輸入音量。 |
| 指定應用程式 | 選擇正在執行的應用程式，再測試收音。 | 需要 Windows build 20348 以上；瀏覽器共用程序時，可能收到其他分頁或視窗音訊。 |

來源測試收到音訊後，仍需開始辨識才能確認是否有人聲及字幕輸出。測試顯示無聲時，先播放內容或對麥克風說話，再重試。

指定應用程式關閉時會停止擷取並提示；重新開啟後請重新選擇。需要登入的網址可在音訊輸入設定指定 Netscape 格式的 `cookies.txt`。

## 準備語音辨識模型

### 下載與選擇模型

1. 開啟「ASR 模型管理」，確認目前使用 CPU 或 GPU 辨識模式。
2. 選擇適合輸入語言的模型，下載至狀態顯示已完成。
3. 開啟「轉錄選項」，選擇相同辨識引擎與模型。
4. 設定輸入語言。固定語言模型只能使用它支援的語言。
5. 回到首頁啟動辨識。

模型管理頁列出的模型以目前套件支援為準。CPU 使用對應的 sherpa-onnx／ONNX 模型，不能直接沿用 GPU 權重。

### CPU 與 GPU 切換

CPU 完整包已包含 CPU 辨識執行環境。CUDA／ROCm 使用者若要切換 CPU 辨識，需確認 CPU ASR Sidecar 已就緒，再準備 CPU 模型；缺少元件時，可匯入 `StreamTranslator-CPU-ASR-Sidecar-v1.5.0.zip`。

辨識模型越大，通常需要更多運算資源。字幕明顯落後時，可先選較小模型，或改用 CPU ASR 搭配雲端翻譯，減少本機模型同時競爭資源。

## 設定翻譯

在「翻譯選項」選擇後端及目標語言，再完成下列對應設定。金鑰請保存在程式設定中，避免出現在公開截圖或問題回報。

### OpenAI

1. 選擇 OpenAI 翻譯後端。
2. 填入 OpenAI API Key 與帳戶可用的模型名稱。
3. 使用測試功能確認連線及翻譯回應。
4. 回到首頁啟用翻譯。

OpenAI 語音辨識與文字翻譯有各自的金鑰設定，請確認填在對應欄位。

### Google Gemini

1. 在 [Google AI Studio](https://aistudio.google.com/app/apikey) 取得 Gemini API Key。
2. 選擇 Google Gemini 翻譯後端，填入金鑰與可用模型名稱。
3. 一般使用保留預設 API 位址，使用測試功能確認回應。
4. 回到首頁啟用翻譯。

雲端服務需要網路，費用、配額與模型可用性依服務商及帳戶而定。

### 程式管理的 llama.cpp 本機翻譯

1. 在「推薦翻譯模型」開啟 GGUF 下載頁，下載模型並放入模型目錄，再到「LLM 模型管理」掃描或匯入。
2. 開啟「Llama 執行設定」，準備與硬體相符的 llama.cpp 執行環境。
3. 選擇 GGUF 模型與顯卡。NVIDIA 優先使用 CUDA；AMD／Intel Arc 獨顯建議使用 Vulkan。GPU 層數為 0 時使用 CPU。
4. 設定伺服器位址與連接埠。預設使用 `127.0.0.1`、埠號 `8081`。
5. 按「啟動伺服器」，確認服務已運行，再執行試譯。已有服務時，變更模型或參數後按「套用並重啟」。
6. 在翻譯設定確認對應端點與模型；預設端點為 `http://127.0.0.1:8081/v1`。

GGUF 是翻譯模型檔，llama.cpp 執行環境負責載入模型，兩者都需準備。本機翻譯顯卡與 ASR 套件類型分別設定；CPU 語音辨識也能搭配 GPU 翻譯。

模型載入時顯存不足，可降低 GPU 層數、上下文長度，或選擇較小模型。請依實際試譯結果調整。

### LM Studio 或其他相容服務

1. 在外部服務啟動模型與 OpenAI-compatible API 伺服器。
2. 在程式選擇相容 API 的翻譯後端。
3. 填入 Base URL、模型名稱與服務要求的 API Key。LM Studio 常見位址為 `http://127.0.0.1:1234/v1`，請以實際服務設定為準。
4. 執行測試翻譯，確認正常後再啟動即時轉譯。

使用外部服務時，先確認該服務已啟動，模型名稱須與服務提供的名稱一致。HY-MT2 與 Index 可分別保存端點、模型、金鑰與提示詞。

## 開始與停止轉譯

開始前確認音源、輸入語言、辨識模型、翻譯後端與目標語言，再按「啟動即時轉譯」。首次載入模型可能需要等待。

先查看原文字幕，再確認譯文：原文錯誤時調整音源或辨識；原文正確而譯文不佳時，再調整翻譯模型、術語或提示詞。

按首頁的「停止即時轉譯」結束任務。更換模型、運算模式或音源前，先停止目前任務，完成設定後重新啟動。

## 調整字幕外觀

開啟「字幕外觀」，調整字型、大小、原文與譯文顏色、透明度、位置及行數，再從首頁按「字幕視窗」或「開啟字幕視窗」確認效果。啟用「滑鼠穿透字幕視窗」後，需回設定關閉穿透才能拖曳字幕。

- 觀看影片或遊戲時，可使用桌面置頂的浮動字幕。
- 只需要譯文時，依字幕顯示設定調整原文與譯文的呈現方式。
- 字幕被背景遮住時，調整文字顏色、背景透明度或位置。
- 設定後以實際字幕預覽確認效果，避免字幕超出螢幕或遮住重要內容。

## 分享字幕到手機或其他裝置

1. 在首頁「字幕分享服務」或「一般設定」的「即時字幕分享」啟用服務。
2. 查看首頁顯示的分享連結或 QR Code。
3. 讓手機、平板或其他電腦連接同一區網。
4. 使用程式顯示的區網網址開啟字幕頁。

其他裝置應使用電腦的區網 IP，不能使用 `127.0.0.1`。若無法連線，確認 Windows 防火牆允許程式連線，且路由器未啟用用戶端隔離。

字幕分享預設用於區網；跨網路使用時，請另行配置具驗證的 HTTPS 或 VPN。

## 匯出字幕與文字

1. 開啟「輸出與通知」，勾選「SRT 字幕」「純文字」或「ASS 字幕」。
2. 選擇需要的格式，例如 SRT、TXT 或 ASS，設定可寫入的輸出資料夾或路徑。
3. 啟動轉譯，確認輸出位置有產生檔案。
4. 停止任務後開啟檔案，確認文字及字幕內容。

需要指定檔案路徑時，副檔名應與格式一致，例如 `.srt`、`.txt` 或 `.ass`。儲存位置以程式目前的輸出設定為準。

## 管理辨識修正與翻譯術語

兩種規則用途不同，請依問題發生的階段設定。

| 規則 | 用途 | 範例格式 |
| --- | --- | --- |
| ASR 修正 | 修正辨識原文中的固定錯字，在翻譯前套用。 | `正確詞,誤辨詞1,誤辨詞2` |
| 翻譯術語表 | 固定角色、作品或專業詞彙的譯名。 | `原文,譯文` |

在對應設定新增或匯入規則後，用包含該詞的音源確認效果。規則支援 CSV／TSV 匯入，使用試算表編輯時請保留文字編碼與欄位格式。

## 更新與備份

1. 備份 `config.yaml`、Cookies、術語與自訂規則，停止辨識與翻譯。
2. 下載與目前 CPU／CUDA／ROCm 類型相同的 App Update 及 SHA-256 清單。
3. 手動更新器選擇 ZIP；CUDA 更新包需下載兩個分卷並放在同一資料夾，再選擇 `.zip.part01`。
4. 依提示完成檢查與套用，更新後確認版本及原本的模型設定。

切換套件類型或無法識別的舊安裝，請改用 Full 完整包。詳細流程請見 [手動更新指南](docs/MANUAL_UPDATE_zh-TW.md)。

模型路徑可在模型管理頁查看；設定保存在程式可寫入位置的 `config.yaml`，字幕輸出位置由輸出設定指定。搬移或重新安裝前，先確認這些資料位置。

## 常見問題

| 問題 | 優先檢查 |
| --- | --- |
| 收不到系統音訊 | Windows 的實際播放裝置是否與程式選擇一致，播放音量是否開啟。 |
| 麥克風沒有聲音 | 麥克風存取權限、輸入裝置與輸入音量。 |
| 直播網址無法解析 | 網址是否有效、是否需登入或地區權限、Cookies 是否仍有效。 |
| 模型下載後仍顯示缺少 | 目前 CPU／GPU 模式、辨識引擎及模型是否與下載項目一致。 |
| 本機翻譯載入失敗 | GGUF 是否完整、執行環境是否相容、記憶體與顯存是否足夠。 |
| API 翻譯沒有回應 | 金鑰、服務位址、模型名稱、網路及帳戶配額，先執行測試翻譯。 |
| 字幕落後或排隊 | 使用較小模型、減少同時使用的本機模型，確認 CPU／GPU 負載。 |
| 固定譯名不一致 | 原文是否正確；正確時使用翻譯術語表，誤辨時使用 ASR 修正。 |
| 手機開不了字幕頁 | 是否在同一區網、是否使用區網 IP、防火牆與路由器隔離設定。 |

若仍無法解決，可在 [GitHub Issues](https://github.com/SakurajimaMai-1202/stream-translator-gpt-floatwindow-ui/issues) 提供版本、套件類型、作業系統、音源、模型及錯誤訊息。日誌通常位於程式附近的 `logs` 資料夾；分享前請移除 API Key、Cookies 與私人網址。
