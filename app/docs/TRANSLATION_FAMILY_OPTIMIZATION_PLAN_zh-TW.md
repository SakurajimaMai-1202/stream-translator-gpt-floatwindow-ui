# HY-MT2 與 Index-Translate 家族優化計畫

日期：2026-10-03  
狀態：實作前計畫；本文不代表模型部署、品質或效能已驗證。  
目標：日文直播轉台灣繁中字幕，提供兩家獨立優化、可操作設定與可重現比較。

## 1. 決策與範圍

保留 HY-MT2 家族優化，新增 Index-Translate 家族優化。兩家各自管理提示詞、推理預設及針對性回退；共用詞庫資料、來源片段、驗證介面與評測工具。沿用 Provider 請求層，不複製整套翻譯管線。

**接入方式已確定：HY-MT2 與 Index-Translate 均視為 API 模型，透過使用者已啟動的 llama.cpp 或 LM Studio OpenAI 相容服務呼叫。** 路徑為「設定頁 → FloatWindow 翻譯流程 → OpenAI 相容 `/v1/chat/completions` → 已載入模型」。沿用端點 URL、模型 ID、必要的 API 金鑰與連線測試；模型載入及服務啟動由 llama.cpp／LM Studio 管理。

本計畫不研究或部署 vLLM，不安裝或執行 Index 官方翻譯 CLI。官方客戶端僅作提示詞格式參考；FloatWindow 的內部啟動參數只用來將設定傳到既有翻譯子程序，不是新增模型部署路線。

第一版交付：

- 明確辨識與手動指定模型家族；選擇模型後顯示適用的優化設定。
- 兩家獨立開關、獨立前文與風格設定；切換後保留各自設定。
- 共用範圍詞庫，區分固定譯名與不確定候選。
- 同一路徑的試譯、驗證、耗時記錄與四組 A/B 比較。
- 舊 HY-MT2 設定相容、異常時有界回退及功能停用路徑。

本計畫不包含 ASR 模型更換、VAD 重寫、微調、配音、Homura 音節控制、NativeLong 長文件翻譯或模型下載打包。一般直播回傳純譯文，序號、時間碼與 SRT 結構由程式產生。採用 Index 不代表目前 Windows、LM Studio 或 llama.cpp 後端已確認相容。

## 3. 功能設計

### 3.1 共用請求與家族策略

共用請求需能表達當前原文、來源／目標語言、已選範圍、命中固定詞、候選詞、有限前文、風格、保留元素與片段識別。內部使用結構化資料，不將整份詞庫或設定頁文字直接拼入提示詞。

家族策略負責把請求轉為模型訊息、支援的推理參數與輸出處理規則。Provider 負責端點通訊；模型家族不由 Provider 名稱推定。支援完整模型名稱的自動辨識，量化別名辨識失敗時允許手動指定；未知模型維持通用策略。

「支援 JSON 保留提示」與「支援 API JSON schema 強制輸出」分開判斷。Index 的硬約束不能直接當成結構化解碼能力。

### 3.2 HY-MT2 專用優化

- 延續現有提示詞與可用設定，先建立行為回歸基準，再調整內容。
- 限制前文句數、字數及命中詞數，明確要求只翻當前句。
- 風格要求保持精簡，保留否定、情緒與省略主詞，不鼓勵自行補全。
- 家族推理預設獨立維護；只有回放證據支持時才變更。
- 針對重述、額外說明與空回覆採用可解釋的異常處理。

### 3.3 Index-Translate 專用優化

- 依官方 instTrans 格式組裝 `【源文】`、編號 `【硬性要求】`／`【注意】` 與輸出指示。
- 已確認的固定譯名與明確保留元素列為硬約束。
- 台灣字幕風格、領域消歧與前文參考列為軟約束；不確定 ASR 候選須標示不確定。
- 明確指定繁體中文及台灣用語，沿用既有繁中處理並檢查其是否改動固定詞。
- 以單一 user 訊息與 temperature 0 作初始 API 試譯基線，實際參數依 llama.cpp／LM Studio 端點支援調整與驗證。
- 請求優先使用 OpenAI 相容欄位，例如 `model`、`messages`、`temperature` 與輸出 token 上限。不得照搬官方客戶端的 vLLM 專用 `extra_body.chat_template_kwargs` 或將 `enable_thinking` 視為通用 API 欄位。
- 若需控制 thinking，僅使用已確認的 llama.cpp／LM Studio 服務設定或端點支援方式；未確認支援時不傳專用參數，也不宣稱已關閉。
- 進階參數僅傳給已確認支援的端點；不因相容性錯誤悄悄取消術語或其他重要翻譯要求。

家族格式、模型尺寸、量化版本與後端效能分開記錄。2B、9B 等不可直接共用已驗證品質或並行數結論。

### 3.4 詞庫與前文

- 固定詞條保存來源詞、指定譯法、範圍及比對模式；區分精確字串與允許變化的譯法。
- 已人工確認的別名可命中固定詞；音近猜測只能成為消歧候選。
- 僅送當前句相關詞，長詞優先；超出上限時記錄排除數。
- 衝突優先序：使用者明確覆寫 → 選定範圍 → 全域詞。同層衝突先提示解決，不依載入順序靜默選擇。
- 跨句一致性第一版以固定詞庫驗證為主。自動新增近期譯名延後實作，避免一次誤譯污染後續字幕。
- 前文有容量上限，切換來源、語言、模型或詞庫範圍時清除；非同步結果不得寫入其他工作階段的記憶。

### 3.5 驗證與有界回退

共用驗證回傳原因碼與嚴重程度。第一版涵蓋空輸出、已知提示詞外洩、前文重述、命中固定詞缺失及指定保留元素改動；長度比例只作提示，避免誤擋合理短答或語言差異。

術語檢查只檢查當前句應出現的詞；保留元素檢查需考慮數量與位置。對帳號、網址等精確元素可先測試佔位保護方案，但必須驗證佔位符是否遺失、重複或錯位，不能只做字串替回。

不把啟發式語意判斷當成可靠的真假裁判。主詞、否定、數字語意與漏譯以人工標註回放驗收。

回退流程：

1. 請求成功後檢查輸出，記錄原始結果與原因。
2. 僅在剩餘字幕時效與排隊預算允許時，最多進行一次修正請求。
3. 修正時可移除前文與非必要風格，但保留固定術語及保留元素；避免靠刪除要求取得假通過。
4. 重試仍失敗或已過時，交由既有失敗字幕機制處理並顯示可辨識狀態，不把原文偽裝成成功譯文。
5. 設定跨層總重試上限，避免 SDK、Provider、管線與驗證重試相乘；過期結果不可覆蓋新字幕。

## 4. 設定與使用流程

使用者選模型／端點後，顯示偵測的家族與手動覆寫入口。模型家族與優化開關分開：關閉優化仍保留該模型必要的基本翻譯模板，只關閉術語、風格、前文等可選增強。

設定頁顯示對應家族的優化區塊，包含啟用、詞庫範圍、風格及前文量；採樣參數與約束細節放在進階區。兩家設定分別保存，共用詞庫可重用。切换家族不能由舊 HY-MT2 端點覆寫成另一個模型。

試譯流程：輸入一小段日文 → 選擇前文與範圍 → 比較基本／優化結果 → 顯示命中詞、驗證狀態與耗時 → 套用設定。試譯必須呼叫直播同一套策略與驗證，不維護獨立提示詞。

舊設定採加法擴充：保留 `hy_mt2_*` 的讀寫相容，新增 `index_translate_*`；共用資料採相容轉接，避免一次改名所有設定。新欄位缺失時有明確預設。新功能先為可選，通過跨直播驗收才考慮改預設。

## 6. 測試與驗收

### 6.1 工程測試

- 家族辨識：官方名稱、常見量化名稱、使用者別名、手動覆寫及未知模型。
- 設定相容：舊設定缺欄位、兩家切換、端點覆寫、儲存重啟與既有翻譯子程序的設定傳遞。
- 提示詞邊界：只翻當前句、無詞庫時的基本模板、候選不變成硬約束、繁中目標。
- 非同步可靠性：切換來源、逾時、過期回覆、空輸出與總重試上限。
- 驗證反例：原文真的重複、極短回答、未命中品牌、料理／國家兩種 `タイ`、保留元素錯位。
- 實際 API 冒煙：使用 llama.cpp／LM Studio 端點測普通字幕、固定術語、短前文、繁中及不支援參數的可辨識錯誤；兩種服務的結果分別記錄。

### 6.2 四組品質比較

固定相同日文、詞庫、風格要求、前文可用範圍，比較 HY-MT2 基本／優化與 Index 基本／優化。各家使用其適合的模板，記錄模型版本、量化、後端及所有參數，不強求相同 token 數。

同時保留原始 ASR 與人工校正日文的對照，區分上游辨識問題與翻譯問題。沿用姊街料理片段作診斷，再加入雜談、遊戲、合作對話與含 BGM 的資料。延續舊計畫目標：12 段、至少 4 個頻道／主要說話者，每段 3–5 分鐘；至少 4 段與 1 個頻道保留到最後，整段直播不得跨開發／留出集。

使用者提供的四張展示圖作案例類型參考，不能代替日文到繁中的測試。分開報告翻譯品質、約束命中與違反原因，不把二元 0／1 解讀為整句翻譯正確率。

### 6.3 發布候選門檻

| 項目 | 判定方式 |
| --- | --- |
| 翻譯品質 | 盲評較好／相同／較差；優化改善數高於退步數，且留出集不得新增關鍵語意錯誤。 |
| 約束遵循 | 分別報固定詞、保留元素與跨句一致性；明確要求的精確元素在驗收集須全部通過，失敗須可追蹤。 |
| 嚴重異常 | 留出集不得出現新增前文重述、提示詞外洩、錯套人名或強制猜測。 |
| 穩定性 | 斷線、逾時與驗證拒絕不停止流程；無跨階段無限重試或過期字幕覆蓋。 |
| 延遲 | 記錄 ASR、組裝、翻譯排隊、推理與端到端 P50／P95，以及實時回放結束時的積壓。 |

| 相容性 | 源碼測試、真實後端、Windows 執行與打包驗證分別記錄；未驗證層級明確標示。 |

## 7. 交付物與回退

交付物包含兩家策略與設定、共用資料及驗證接線、可操作試譯頁、回歸測試、固定回放清單、品質／延遲報告與設定相容說明。日誌預設只存原因碼、數量及耗時；完整字幕與提示詞僅在明確啟用除錯或評測時保存，排除金鑰。

停用某家優化應回到該模型的基本翻譯路徑；切換回 HY-MT2 可恢復原設定。不得為回退覆寫共用詞庫或清除其他模型設定。未通過留出驗收的策略保持實驗性、可選，保留既有預設。

## 8. 主代理與子代理結構

本節是後續實作的派工結構；撰寫此結構不代表已啟動代理或開始功能實作。採一位主代理、最多三位同時工作的子代理。依工作相依分批執行，不以模型家族切成兩個會同時修改核心檔案的團隊。

### 8.1 主代理責任

- 開工前記錄 Git 狀態與相關檔案差異，辨識既有未提交工作；不得覆寫或清理使用者變更。
- 檢查適用的 AGENTS.md，確認兩條翻譯入口、現有測試與可用端點。先訂請求、回應、設定欄位及錯誤碼契約，再派發修改工作。
- 分配每個檔案的唯一寫入者，管理契約變更與代理交接。子代理需要越界修改時先報位置與原因，由主代理調整責任範圍。
- 處理跨模組整合與相依問題；整合期間先讓原負責者停止修改該檔案，避免競爭寫入。
- 統一決定功能預設、總重試上限、前文清除規則及延遲預算，避免不同代理各自決定。
- 檢查測試證據、主持介面與端到端驗收，向使用者報告已完成、待驗證與限制。主代理持續負責直到整體交付，不把子代理完成訊息等同產品完成。

| B：設定與產品接線 | `app/backend/core/config_manager.py`、`translator.py`、`llm_translator.py`、`app/backend/api/translation.py`、`stream-translator-gpt/stream_translator_gpt/main.py`、`pipeline_runner.py`、`app/frontend/src/views/SettingsView.vue` 及必要設定型別／store | 完整設定傳遞、API 請求接線、相容設定及可操作試譯。呼叫 A 的策略與驗證，不複製提示詞或重試邏輯。 |
| C：獨立驗證 | 主代理分配的新測試檔、回放工具及專用評測輸出目錄 | 設計反例、執行 API／UI／回放驗收並提出缺陷。原則上不改產品原始碼，發現問題交回 A／B；驗證不可只重述實作邏輯。 |
| 主代理 | 本計畫、契約與整合紀錄，以及正式交接後的跨模組修正 | 最終整合、審查與交付；不在子代理仍寫入時修改其檔案。 |

A／B 可修改自己負責功能的既有測試，但派工時須列出具體檔名。C 的測試檔與工具檔另外指定，三者不可同時編輯同一測試檔。依賴或建置設定變更由主代理統一審查與安排。

### 8.3 先固定的共用契約

主代理在第一輪派工前記錄下列決策，A／B／C 均依同一版本實作與驗收：

1. **模型與端點**：家族值、手動覆寫、端點 URL、model ID 與支援參數；兩家均走 llama.cpp／LM Studio OpenAI 相容 API。
2. **設定**：保留既有 `hy_mt2_*`，新增 `index_translate_*`；明確列出預設、關閉優化的行為及詞庫範圍。
3. **請求資料**：當前句、語言、確定術語、候選、前文、保留元素、風格、工作階段識別與時效資訊。
4. **結果資料**：譯文、命中詞、驗證原因、重試次數與耗時；敏感原文只在明確啟用的評測／除錯路徑保存。
5. **狀態生命週期**：來源或設定切換後哪些記憶清除、過期回覆如何丟棄、誰持有整體重試預算。
6. **試譯介面**：沿用或擴充現有 API 的請求與回應格式，必須呼叫直播同一套策略及驗證。

契約變更須由主代理同步給受影響代理；不得以臨時欄位或相容猜測讓兩邊各自繼續。

### 8.4 執行批次與相依順序

| 批次 | 主代理 | A | B | C | 進入下一批的條件 |
| --- | --- | --- | --- | --- | --- |
| 0：準備 | 記錄現況、固定契約與檔案所有權 | 盤點核心策略與 HY-MT2 基準 | 盤點設定到 API 的路徑 | 整理反例、資料清單及測試缺口 | 契約與寫入範圍清楚；缺少端點或素材已明確記錄。 |
| 1：可並行實作 | 協調契約、審查跨模組問題 | 完成家族策略與共用控制 | 完成設定相容、內部傳遞與 UI；依契約準備試譯接線 | 撰寫獨立測試與回放工具，可用 mock 驗證協定 | 核心介面與設定路徑可整合；mock 不算真實模型通過。 |
| 2：整合 | 統一接線、檢查回歸與責任交接 | 修正核心缺陷 | 完成共用試譯接線與介面修正 | 驗證儲存重啟、切換、逾時與真實 API | HY-MT2 回歸、Index 接入及操作流程通過；缺項明確列出。 |
| 3：品質驗收 | 排定資源時段、判讀報告與決定預設 | 依開發集結果修正策略 | 修正結果呈現與設定問題 | 四組比較、端到端回放、留出集驗收 | 達到第 6 節門檻，或明確交付為待驗證的實驗功能。 |

A、B、C 可以平行讀取與開發，但真實模型測試由主代理排程。共用 GPU 或同一 API 服務時，避免同時跑多組效能測試；端到端測試仍須包含正常 ASR 與翻譯競爭 GPU 的情境。C 不因測試需要自行切換使用者目前載入的模型或覆寫既有輸出；需要影響現行服務的操作交由主代理確認授權與時段。

### 8.5 每位子代理的派工與回報格式

派工需包含：

```text
目標：本輪可驗收的結果。
依據：本計畫的具體章節與已固定契約版本。
可修改：明確檔案清單；其餘檔案可讀，修改需交接。
輸入與相依：已就緒介面、仍待其他代理交付的項目。
完成條件：行為、測試及證據，不能只回報程式已寫好。
限制：API 接入限定 llama.cpp／LM Studio；保留既有未提交工作。
```

完成回報需包含：變更檔案、實際行為、執行的測試與結果、未驗證項目、契約變更需求、已知缺陷與交接注意事項。子代理不自行宣告整體發布就緒；無真實模型端點時可完成離線工程驗證，API 品質與效能保持待驗證。

### 8.6 最終整合門檻

主代理逐項核對：

- A／B 使用同一份請求、設定與回應契約，試譯和直播未分叉提示詞。
- Index 與 HY-MT2 各自保存設定，切換不造成端點或模型覆寫。
- C 的反例測試與實際畫面驗收有具體結果；失敗由負責代理修正後重新驗證。
- 明確區分來源碼測試、真實 API、端到端品質、Windows 執行與打包驗證。
- 只有完成所需品質與延遲驗收的設定才能升為推薦預設；素材或服務不足時列出缺口。
- 最終報告包含檔案、驗證證據、限制與回退方式；提交、打包及發布依當次授權處理。

### 8.7 模型派工與成本控制

代理角色與模型選擇分開管理。主代理負責決策並不表示必須使用最昂貴模型；測試代理也不能因使用較低成本模型而省略必要證據。

2026-10-03 核對官方模型文件：GPT-6 Astra 定位為最複雜推理與程式工作，GPT-6.1 Sol 平衡能力與成本，GPT-6 Luna 適合明確、重複及大量任務。因此成本優先的按需升級方向是 **Luna → Sol → Astra**，而非 Luna → Astra → Sol。這是派工策略，不保證每個具體任務的成功率都依相同順序排列。

| 角色 | 成本優先建議 | 升級或交接條件 |
| --- | --- | --- |
| 主代理 | GPT-6.1 Sol | 跨模組契約出現矛盾、難以定位的併發／狀態問題，或重大設計無法可靠收斂時，安排 Astra 定點分析或審查。 |
| A：翻譯核心 | GPT-6.1 Sol | 有重現證據且合理修正仍失敗、前文與回退生命週期互相干擾時，交 Astra 處理具體問題。 |
| B：設定／API／UI | GPT-6.1 Sol | 小型明確修改可拆給 Luna；涉及未釐清的跨模組行為先由主代理收斂，必要時交 Astra。 |
| C：獨立驗證 | GPT-6 Luna | 執行測試、整理 log、建立清楚的反例；複雜失敗歸因交 Sol，矛盾結果或疑難問題再交 Astra。 |

使用者提出的 **主代理 Sol＋A Astra＋B Astra＋C Luna** 保留為備選配置，可用於希望 A／B 直接投入較高能力模型的實作批次；不能把它描述為比 Sol 主力方案便宜。模型配置由實作派工時明確選定，本節不代表已切換当前聊天模型或啟動任何子代理。

成本說明：官方 Standard 短上下文 API 價格在核對時每百萬輸入／輸出 token 分別為 Astra US$10／50、Sol US$2／10、Luna US$0.10／0.50。這只能比較同等用量下的 API 單價，不能直接換算本次 Codex 訂閱額度、帳戶帳單或實際任務總成本；後者還受推理量、上下文、重試、快取及服務等級影響。執行前如需金額預算，重新核對當時價格與計費方式。

具體節省方式：

- 派工只提供任務摘要、契約、負責檔案與必要證據；避免每個子代理都載入完整聊天與全庫內容。
- 主代理一次完成共用盤點，子代理只補查自己的範圍。長 log 保留為檔案，回報失敗摘要與定位資訊。
- 搜尋、格式檢查及已知測試優先用工具直接執行；不要為單一短命令額外啟動代理。
- 已通過測試只在新修改或新證據涉及該範圍時重跑；保留必要的最終整合驗證。
- 同一問題在兩次有證據的修正後仍失敗時，停止盲目重試，提交重現方式、已排除原因與相關差異，由主代理決定縮小問題、補資料或升級模型。
- 缺少服務、素材或權限不是模型能力問題；升級模型不能代替補齊條件。
- 升級時交接問題摘要與必要檔案，不重做整個任務。高成本模型完成定點工作後，後續明確工作回到原配置。
- 最多維持主代理加三個活躍子代理；需要 Astra 介入時先交接並釋出一個子代理名額，不額外常駐第四位子代理。
- C 的自動測試通過不代表日文譯意已由人工驗證；模型初評不得取代第 6 節要求的品質驗收。

派工與完成回報補充記錄模型、推理設定、重試次數、耗時及可取得的 token 用量。未取得用量時標示未知，不估造節省百分比。模型設定須以工具實際接受的可用識別碼為準；本輪只更新文件。
