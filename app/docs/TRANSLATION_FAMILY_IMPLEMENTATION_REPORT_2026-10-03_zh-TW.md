## 真實 API 短句測試更新

使用者提供憑證後，端點 `http://192.168.100.181:8123/v1` 認證成功。LM Studio 模型狀態顯示已載入 `index-translate-9b` 與 `hy-mt2-7b-i1`（其模型檔 key 為 q6_k）；僅對這兩個已載入模型依序請求，沒有切換或載入其他模型。金鑰只用於測試程序環境，未寫入來源、設定或報告。

每個模型測三種合成案例的基本／優化模式，共 12 次請求，均成功取得譯文；另經应用试譯 API 路徑各跑基本／優化固定詞案例，共 4 次，均成功。指定「星街すいせい → 星街彗星」有保留。單次短句耗時含首次請求約 Index 0.48–1.47 秒、HY 1.01–2.12 秒；樣本少且包含冷／暖請求，不能用此判定速度勝負或直播 P95。

**語意失敗案例：**「今日は魚料理を作ります。」作前文，「タイを塩で焼きます。」作當前句，Index 基本輸出「用鹽將泰國烤熟」，優化輸出「用鹽將泰國菜烤一烤」；HY 基本／優化均輸出「用鹽將泰國魚烤熟」。兩家未正確消歧成鯛魚；程式驗證未拒絕這些輸出，因未指定該固定詞。這證實現有自動驗證只能檢查已知要求，不能作语意正确性的保證。

無憑證的合成結果保存於 `benchmark-results/index-family-validation-20261003/live-api-index_translate-result.json`、`live-api-hy_mt2-result.json`、`live-app-index_translate-result.json` 與 `live-app-hy_mt2-result.json`。測試工具 `live_api_smoke.py` 接受程序環境金鑰，不含憑證；此工具是短句冒煙，尚非完整跨直播評測。

## 桌面環境 OpenCC 修復

使用者截圖中的桌面後端實際由 `F:\AI\floatwindow\.venv\Scripts\python.exe` 啟動；該環境缺少 OpenCC，而先前的 build-runtime-cache 有此套件。已在桌面 .venv 安裝 opencc-python-reimplemented 0.1.7，並驗證繁中轉換。後端依賴清單與兩份 GUI 打包 spec 也補上 OpenCC 模組及字典／設定資源收集；資源收集與 spec 語法檢查通過，尚未重打 EXE。
